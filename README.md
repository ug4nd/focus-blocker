# focus-blocker

Блокировщик отвлекающих программ для Windows 11. Во время рабочих блоков из
`plan.json` закрывает процессы из чёрного списка (браузеры, Steam, Discord).
Процессы из белого списка (VMware, VLC, Throne VPN, Claude) не трогает никогда.

## Установка

Нужен Python 3.13.

```
pip install psutil
```

## Запуск

```
python blocker.py            # работает в цикле, остановка по Ctrl+C
python blocker.py --once     # одна проверка и выход
python blocker.py --config путь\к\plan.json
```

**Сначала запустите в режиме `dry_run`** (он включён по умолчанию): программа
только пишет в лог, что закрыла бы. Когда убедитесь, что список верный,
поставьте `"dry_run": false` в `plan.json`.

Лог пишется в консоль и в `blocker.log`.

## Разблокировка на сегодня

Во втором терминале, пока блокировщик работает:

```
python blocker.py --unlock
```

1. Программа печатает случайный код из 30 символов, его нужно набрать точно.
2. Запускается обратный отсчёт 5 минут. Ctrl+C отменяет разблокировку.
3. По окончании создаётся `unlock.flag` с сегодняшней датой.

Основной процесс не останавливается: до полуночи он ничего не закрывает, а
завтра блокировка включается сама (устаревший `unlock.flag` удаляется).
В `blocker.log` пишутся время запроса, отмены (или неверного кода) и срабатывания
разблокировки.

Это защита от импульса, а не от злого умысла: процесс можно завершить в
Диспетчере задач, а флаг создать руками.

## Один экземпляр

Повторный запуск `python blocker.py` сообщает, что блокировщик уже работает, и
завершается. Для этого используется `blocker.lock` (PID и время создания
процесса, чтобы устаревший lock после сбоя не мешал). `--unlock` и `--once`
этому ограничению не подчиняются.

## Формат plan.json

| Поле | Описание |
|---|---|
| `check_interval_seconds` | Как часто проверять процессы (по умолчанию 5). |
| `dry_run` | `true` — только логировать, `false` — реально закрывать. |
| `work_blocks` | Список блоков: `days` (`mon`…`sun`), `start`, `end` в формате `HH:MM`. Конец не включается. Блок с `start` позже `end` переходит через полночь и относится ко дню начала. |
| `blacklist` | Имена процессов для закрытия. |
| `whitelist` | Имена процессов, которые нельзя закрывать. Имеет приоритет над `blacklist`. |

Имена сравниваются целиком, без учёта регистра (`msedge.exe` не заденет
`msedgewebview2.exe`). Точное имя процесса смотрите в Диспетчере задач на
вкладке «Подробности».

## Защита

- Whitelist всегда главнее blacklist.
- В коде есть встроенный список системных процессов (`explorer.exe`,
  `csrss.exe`, `svchost.exe` и др.), которые не закрываются, даже если попали в
  blacklist.
- Программа не закрывает собственный процесс.
- Битый `plan.json` — программа сообщает об ошибке и завершается, ничего не закрывая.

## Ограничения

- Процессы, запущенные от администратора, без прав администратора закрыть не
  получится (в логе будет `access denied`).
- Сначала процессу отправляется `terminate()`, через 3 секунды — `kill()`.
  Несохранённые данные в закрываемых программах могут быть потеряны.
- Закрытие браузера закрывает и вкладку с claude.ai.
- Программа не запускается сама при старте системы и не защищена от остановки.
